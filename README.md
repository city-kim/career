# 김찬태 | Senior Frontend Developer

[포트폴리오 사이트](https://city-kim.github.io/career), [GitHub](https://github.com/city-kim), [이메일](mailto:nkdevil@naver.com)

메시징, 커머스, 게임 플랫폼과 SaaS에서 프론트엔드 개발, 공통 개발 기반 설계와 운영 업무 개선을 담당해 왔습니다. 프레시지에서는 허닭몰 재구축을 포함한 7개 프로젝트를 수행했고, 현재 티모웍스에서는 한국과 일본 기업용 근태관리 SaaS TEMPO를 개발하고 있습니다.

Claude Code와 Codex를 활용하는 개발 하네스를 구성하고, 생성 코드를 직접 검토하며 테스트로 검증합니다. 다른 직군의 동료가 겪는 문제에도 관심을 갖고 목적과 제약을 함께 확인하며 가능한 대안을 제안합니다.

## 주요 문제 해결 경험

- **허닭몰 전시 빌더:** 다단으로 중첩되는 템플릿과 모듈의 역할을 나누고, 상품, 카테고리, 쿠폰 검색과 선택을 공통 컴포넌트로 구성했습니다. 운영자가 전시 화면을 직접 구성하고 게시 시각을 예약하도록 개발했습니다.
- **전시 데이터 제공:** 반복 API 호출 부하와 로딩 속도를 고려해 백엔드와 사전 생성 방식을 협의했습니다. 프론트엔드는 10분 주기로 S3에 갱신된 데이터를 조회하며, 전시 정보의 반영 시점도 해당 배치 주기에 따릅니다.
- **TEMPO 근태 계산:** 자정을 넘기는 교대근무, 부분휴가, 휴게시간, 지각 유예를 공통 입력과 계산 경로로 처리했습니다. 휴가 차감과 실근로의 휴게 공제를 분리하고 조합별 테스트로 검증했습니다.
- **PDP 일정 화면:** 기존 달력의 구성과 성능 제약에 대응해 업무, 휴무, 기간별 좌표로 그리는 달력을 직접 구현했습니다. 같은 기간과 업무 데이터를 적용해 기존 라이브러리 대비 5배 이상 빠른 렌더링을 확인했습니다.
- **게임 운영 리포트:** 매월 반나절 동안 작성하던 수동 리포트를 자동 생성하도록 전환했습니다. 같은 기간의 수동 리포트와 수치, 셀 병합, 서식을 대조해 확인했습니다.
- **홈페이지 재구축:** 클라이언트 JavaScript를 줄이기 위해 RSC 기반 서버 렌더링을 선택했습니다. Lighthouse 40~50점대에서 80점 후반대, 데스크톱 LCP 2초 이내를 확인했으며, Swiper의 클라이언트 로딩 부담은 남았습니다.
- **ALIGO 점진적 개선:** 기존 PHP 구조를 유지하면서 Vue를 적용하고 데이터 바인딩과 함수 공통화로 반복 수정 작업을 줄였습니다.

## 기술과 검증

- **Frontend:** React, Next.js, Vue.js, TypeScript, Tailwind CSS, TanStack Query
- **Mobile:** React Native, Expo
- **Backend와 데이터:** NestJS, Node.js, Express, Koa.js, Prisma, PostgreSQL, MySQL, MongoDB
- **테스트와 배포:** Vitest, Playwright, Storybook, Chromatic, Docker, GitHub Actions, AWS
- **AI 활용:** 프로젝트 문맥과 작업 지침 직접 구성, 기존 리뷰 에이전트와 스킬 도입, 생성 코드 직접 검토와 자동화 검증

TEMPO 웹 서비스는 2026.09.12 공개했고, 직원용 앱은 Google Play와 App Store에 출시했습니다. 급여, 월말정산, 증명서 발급은 Beta입니다. ALIGO V2는 개발 후 출시 전에 폐기됐습니다.

허닭몰의 가입 회원은 100만 이상이며, 최근 1년간 주문, 로그인 등 활동 기준 활성 사용자는 약 20만 명입니다. ALIGO npm 패키지의 사용 고객 비율과 측정 조건이 확인되지 않은 성능, 전환율 수치는 기재하지 않았습니다.

## 로컬 실행

```bash
npm install
npm run dev
```

| 명령어                 | 설명                 |
| ---------------------- | -------------------- |
| `npm run dev`          | 개발 서버 실행       |
| `npm run build`        | 배포용 빌드          |
| `npm run lint`         | TypeScript 타입 검사 |
| `npm run format:check` | 코드 서식 검사       |

GitHub Pages 배포 시 `STATIC_EXPORT=true`, `NEXT_PUBLIC_BASE_PATH=/career`를 설정해 정적 파일을 생성합니다. 기본 브랜치에 반영된 변경은 GitHub Actions 배포 워크플로를 통해 공개됩니다.

- `data/portfolio.ts`: 대표 프로젝트, 경력, 기술 데이터
- `data/additional-projects.ts`: 사내 시스템, 운영 개선, 초기 경력 프로젝트
- `data/project-types.ts`: 프로젝트 범위, 문제 해결 사례와 화면 자료의 타입
- `components/portfolio/project-dialog.tsx`: 배경, 문제 해결 사례, 담당 내용, 구현 화면
- `docs/project-sources.md`: 설명과 기존 화면 캡처의 근거

플랫폼실

한 명이 다섯 개 서비스를 감당하는 구조 만들기

배경

플랫폼실의 프론트엔드 개발자는 저 한 명이었고, 백엔드 개발자 두 명과 함께 자사 홈페이지, 플랫폼 홈페이지, 플랫폼 어드민, 에테르나 GM Tool, 러브라이브 BI까지 다섯 개 서비스를 동시에 맡아야 했습니다.

문제

서비스마다 화면을 처음부터 만들어 나가는 방식으로는 한 사람이 다섯 개를 감당할 수 없었습니다. 게다가 운영 툴은 앞으로도 계속 늘어날 예정이었기 때문에, 늘어나는 속도를 감당할 방법이 필요했습니다.

판단

요청받은 화면부터 만들지 않고, 공통 기반을 먼저 만드는 순서를 선택했습니다. shadcn/ui 기반 Headless UI로 백오피스 공통 컴포넌트를 표준화하고, 인증과 레이아웃까지 포함한 통합 패키지를 설계하여 모든 운영 툴이 같은 기반을 공유하도록 했습니다.

결과
  • 공통 패키지를 사내 모든 운영 툴에 적용했고, 새 어드민이 필요해질 때 초기 세팅 없이 곧바로 기능 개발에 착수할 수 있게 되었습니다.
  • 에테르나와 러브라이브 등 서로 다른 어드민 사이에서 UI 일관성을 확보했습니다.
  • 같은 기간에 진행한 자사 홈페이지 리뉴얼에서는 워드프레스를 Next.js App Router 기반으로 재구축하여, Lighthouse 성능 점수를 40~50점대에서 80점 후반대로 올리고 LCP를 0.2초 이내로 단축했습니다.
비고

회사가 폐업하여 서비스 화면과 저장소를 공개할 수 없습니다. 설계 의도와 구현 내용은 면접에서 상세히 설명해 드릴 수 있습니다.

Tech실

20만 사용자 커머스를 자체 플랫폼으로 재구축

배경

약 20만 명이 방문하는 커머스 허닭몰은 메이크샵 위에서 운영되고 있었습니다. 프론트엔드 3인 팀에서 아키텍처 설계와 공통 구조 구축을 맡았습니다.

문제

플랫폼의 커스터마이징 제약 때문에 개선할 수 있는 범위가 좁았습니다. 특히 운영팀이 홈이나 기획전 화면을 하나 바꾸려면 개발팀에 제작을 요청하고 2~3일을 기다린 뒤, 지정한 시간에 맞추어 수동으로 업로드해야 했습니다.

판단
  • Next.js 기반 자체 플랫폼으로 전환하고, Turborepo 모노레포로 공통 모듈을 분리했습니다.
  • AWS Elastic Beanstalk에 CI/CD를 구성하고, S3와 CloudFront로 정적 자원을 최적화했습니다.
  • Storybook, Chromatic, Playwright로 UI 및 E2E 테스트 환경을 구축했습니다.
  • 운영자가 UI 구성 요소를 직접 조합하는 템플릿 기반 전시 빌더를 만들었습니다.
결과
  • 차세대 허닭몰을 정식 오픈했고, 이미지가 많은 페이지에서도 로딩 속도를 0.2~0.5초 수준으로 유지했습니다.
  • 전시 준비 과정이 개발팀 요청과 대기에서, 운영자가 직접 구성하고 게시 시간만 예약하는 방식으로 바뀌었습니다.

차트 대시보드만 만들고 끝내지 않고, 백엔드와 협의하여 서버 데이터를 기반으로 리포트를 자동 생성하고 내려받는 기능을 함께 구현했습니다. 배포 환경에서는 단일 서버를 효율적으로 쓰기 위해 Nginx 리버스 프록시 구성을 제안했습니다.

결과
  • 월간 리포트 작성이 반나절에서 클릭 한 번으로 바뀌었습니다.
  • 대시보드는 한국과 일본의 운영 인력 10여 명이 상시 사용하는 도구로 자리 잡았습니다.
